# Arvexo Radar: не-цели

**Версия:** v0.1.0 — Hackathon MVP
**Статус:** продуктовая спецификация

## 1. Назначение

Документ ограничивает scope и предотвращает появление функций, не требуемых кейсом КРОК или [целями продукта](./05-product-goals.md).

## 2. Не-цели v0.1.0

### NG-01. Не AI-чат и не рабочий агент

Radar не исполняет пользовательские задачи из анализируемых запросов, не заменяет почтового, CRM-, Jira- или календарного агента.

### NG-02. Не оценка сотрудников

Radar не строит рейтинги, профили продуктивности или выводы о намерениях отдельных сотрудников. Поля пользователя допускаются только для безопасных агрегатов при утверждённом доступе.

### NG-03. Не доказательство ROI

По одним логам продукт не доказывает экономию времени, финансовую отдачу или качество ответа агента. Такие выводы требуют outcome-данных.

### NG-04. Не универсальная BI-платформа

MVP не предоставляет произвольный конструктор запросов, отчётов, формул и визуализаций.

### NG-05. Не мониторинг инфраструктуры LLM

Latency моделей, GPU utilization, token billing и uptime агентов не являются предметом Radar, кроме технических метрик собственного pipeline.

### NG-06. Не online streaming

MVP анализирует загруженный dataset batch-процессом. Постоянный ingest из корпоративных систем и real-time alerts не входят в scope.

### NG-07. Не готовый набор enterprise-интеграций

Прямые коннекторы к CRM, почте, Jira, Confluence, календарям и DWH не реализуются. Их упоминание в примерах ТЗ описывает содержание запросов, а не интеграции Radar.

### NG-08. Не полнофункциональный IAM

Архитектура предусматривает identity и authorization boundary, но SSO, SCIM, сложные роли и tenant administration не обязательны для Hackathon MVP.

### NG-09. Не обучение foundation model

MVP не обучает собственную LLM и не использует H100. Допускаются локальные embedding/classification models и подключаемый локальный LLM provider для тестов.

### NG-10. Не гарантированное обнаружение любой PII или секрета

Маскирование снижает риск, но не заменяет DLP и правовую оценку. UI и документация не должны обещать абсолютное обнаружение.

### NG-11. Не ручная разметочная платформа

Полный annotation workflow, active learning UI и управление taxonomy командой не входят в MVP. Исправление результатов может быть последующим направлением.

### NG-12. Не production SLA

Круглосуточная поддержка, disaster recovery, multi-region и формальные SLA не входят в v0.1.0, хотя базовые health checks и резервируемая архитектура описываются.

### NG-13. Не автоматическое действие

Рекомендации не запускают агентов, автоматизации, обучение или организационные изменения без решения человека.

### NG-14. Не произвольные форматы файлов

MVP принимает только форматы, явно утверждённые [Dataset Specification](./08-dataset.md); архивы, документы и исполняемые файлы отклоняются.

## 3. Правило изменения scope

Новая крупная функция включается только после обновления Vision/Goals, Functional Requirements, Security и Roadmap. Формулировка «приветствуются вау-фичи» из ТЗ не является автоматическим разрешением расширять scope.
